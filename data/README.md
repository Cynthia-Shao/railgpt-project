# Data Directory

RailGPT 项目的本地数据目录，用于存放规则、调度场景和历史案例等数据文件。

## 目录说明

- `data/rules/`：规则总目录
- `data/rules/hard_rules/`：强规则库。这里的规则属于硬约束，大模型和优化算法必须优先使用，任何情况下都不能违反
- `data/rules/soft_rules/`：普通规则库。这里的规则属于软约束，可用于方案优化、解释生成和候选排序，但优先级低于强规则
- `data/scenarios/`：调度场景输入、扰动事件、测试场景等
- `data/cases/`：历史调度案例、人工方案、对比样本等

## 多库结构建议

当前建议至少维护以下几类知识库：

- 强规则库：不可违反的安全约束、行车规则、调度红线、设备边界条件
- 普通规则库：经验规则、优先级策略、常见调整原则、组织规范
- 场景库：实际调度输入、扰动描述、测试样例
- 案例库：历史处理方案、人工经验方案、对比结果

## 规则优先级

系统后续会按以下顺序使用规则：

1. 优先检索并注入 `hard_rules/` 中的强规则
2. 任何生成、优化、改写后的调度方案都必须通过强规则校验
3. 在满足强规则的前提下，再参考 `soft_rules/` 中的普通规则做方案优化和排序

## 推荐文件格式

- 优先使用：`json`、`jsonl`、`csv`、`md`、`txt`
- 也可以使用：`yaml`

## 建议

- 文件名尽量语义化，例如 `headway_hard_rule.json`、`dispatch_priority_soft_rule.json`、`delay_scenario_01.json`
- 如果同一类数据字段风格不一致，先都放进来，后续会统一清洗和接入
